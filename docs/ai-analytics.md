# AI analytics: research and implementation

Researched November 15, 2026. The UI examples contain deterministic synthetic observations, fictional model names, and fictional rates. They are not provider benchmarks or live telemetry.

## Implemented views

| Question | Graphic | Definition / interpretation |
| --- | --- | --- |
| How much are we using? | Stacked area | Daily uncached input + cached input + output. Cached input is part of input, not an extra token category to add twice. |
| Which models cost more? | Donut + labeled values | Sum recorded cost by model in USD; demo rates are fictional. Production should use billing/provider usage records and dated rates. |
| Where are users waiting? | Multi-series line | Successful-request duration p50/p95 and TTFT p50 in seconds. Demo duration is model-call time, not full user-perceived end-to-end time. |
| How quickly is output generated? | Line | Mean output tokens divided by duration after the first token, over successful requests. This differs from traffic throughput (requests/s) and rate limits (tokens/min). |
| How often do requests fail? | Percentage line | Error attempts / all attempts in the same period; fixed 0–100% axis. |
| Are there long-tail outliers? | Histogram | Duration buckets over all attempts; lower-inclusive and upper-exclusive. |
| Which quality dimensions regress? | Heatmap | Per-rubric pass percentages on a fixed 200-case synthetic eval set. Include dataset/rubric version and sample count in real data. |
| Is RAG finding and using evidence? | Grouped bars | Context precision, context recall, and faithfulness, separately named. Scores are benchmark metrics, not confidence probabilities. |
| What is the cost/quality trade-off? | Scatter | USD per 1,000 equivalent requests versus evaluation pass percentage on the same benchmark. A comparison needs matched datasets/settings. |
| Where do agent runs stop? | Stage bars | Nested cohort: started → planned → tool success → completed. These are run counts, not a sum of tool calls. |
| What happened on individual calls? | Paginated table | Request ID, model, status, tokens, duration, and cost. Search before pagination; change page size; preserve accurate counts. |

Operational filters (window/model) affect operational charts and the request log. Eval/RAG/trade-off/agent examples explicitly use separate fixed synthetic cohorts and do not respond to those filters.

## Why these choices

[OpenAI latency guidance](https://developers.openai.com/api/docs/guides/latency-optimization) distinguishes first-token delay, complete-response delay, and output speed. Percentiles must be computed over underlying observations or merged histograms, not averaged across daily p95 values. This demo uses nearest-rank percentiles and excludes failed requests from successful-request latency summaries.

[OpenAI evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices) recommends task-specific objectives, representative datasets, and ongoing comparison calibrated with human judgment. A single generic quality score is insufficient; the heatmap exposes separate dimensions and sample sizes.

[Ragas metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) distinguish retrieval precision/recall, answer faithfulness/relevance, and agent/tool metrics. Keep those definitions distinct instead of labeling every score “accuracy.”

[OpenTelemetry GenAI conventions](https://github.com/open-telemetry/semantic-conventions-genai) are the integration reference for production event/metric names; the former opentelemetry.io GenAI metrics page now redirects there. Confirm the current convention version when implementing ingestion. No collector or telemetry backend is included here.

## Component implementation

The table follows [shadcn's TanStack Table composition](https://ui.shadcn.com/docs/components/radix/data-table), with the installed v9 feature API. Charts follow [shadcn's Recharts composition](https://ui.shadcn.com/docs/components/radix/chart), with the installed Recharts v3. They are project-owned implementations adapted to Sky UI tokens; no claim is made that these files were generated by the shadcn CLI.

Reusable exports: DataTable, ChartContainer, ChartTooltipContent, CartesianChart (line/area/bar), DonutChart, ScatterPlot, and Heatmap. All colors and chart height come from theme tokens. Numeric values in charts are data, not fixed CSS dimensions. Animations are disabled, legends label series, and each plot has an expandable HTML table so values are available without hovering or relying on color alone.

DataTable currently performs client-side pagination over the complete supplied dataset. Do not pass a single server page while claiming its counts describe the whole collection. A future server-paginated variant needs controlled page state, total row count, backend search/sort, and cancellation of stale fetches.

## Additional production metrics to consider

Depending on the workload: cached-token ratio, request throughput, queue time, retries/timeouts/rate limits, retrieval latency and zero-result rate, tool-call accuracy, agent loop counts, human acceptance/escalation rate, safety false positives/negatives, training/validation loss, classification confusion matrices, calibration and drift, GPU utilization/memory, and feedback coverage. Each requires an explicit denominator, units, sampling window, and data source. The current demo does not claim to instrument these signals.

Do not collect raw prompts, retrieved documents, or user identifiers merely to populate aggregate charts. Keep aggregation and authenticated telemetry access in the application/backend layer, outside the shared UI package.
